# Sugarat Pocket Companion

[English](README.md) | 中文

## 概述

六个原创动态角色族群在 SDGoods 360×360 圆屏徽章上共用现有温和的 epet 养成模拟。初始伙伴为 Ember（火苗）、Leaf（叶灵）或 Cloud（云团）；双亲配对可产生 Sprout（荧芽）、Glow（霞团）和 Willow（绒叶），继承血统并呈现个体差异。应用构建为单个 `sugarat_pet.bin`。[验证记录](validation.json) 区分原生测试、固件编译和实体设备验收。

<a id="controls"></a>
## 操作

主页突出动态伙伴，仅保留名字、成长标签和底部快捷入口。点击入口或从屏幕下部上滑，包括从伙伴脚边起手，可展开六个带文字的图标：投喂、玩耍、睡眠或唤醒、状态、家族和碰面。每个按钮为 72×64 像素，横竖间距均为 10 像素，点击间隙不执行动作。竖向移动超过 10 像素后面板跟手移动，松手后自动展开或收起；向下滑动或点击面板上方也可关闭。移动期间和面板展开时暂停背景绘制。BSP 按压所有权和带位移守卫的点按避免滑过按钮时执行动作；顶部系统控制仍由 BSP 管理。状态页提供清洁。家族页通过左右滑动浏览伙伴和蛋，两端不循环；初次选择伙伴也使用相同手势。左上角 Back 返回键的触摸区为 72×72，退出浏览时不改变当前养成伙伴。底部 Select 确认键的触摸区为 152×56，确认后继续照顾浏览到的成员或陪伴孵蛋。蛋准备好后点击即可孵化。固件界面使用英文。

<a id="build"></a>
## 构建

激活 ESP-IDF 5.5.4、ESP32-S3 工具链、CMake 和 Ninja，再从仓库根目录运行：

```sh
idf.py -C plays/sugarat-pet -B /tmp/sugarat-pet-build build
```

镜像为 `/tmp/sugarat-pet-build/sugarat_pet.bin`，项目身份为 `sugarat_pet`，固件版本为 0.2.2。美术资源编入应用，参考分区表保持不变。应先核对设备的实际布局和可用容量，再通过其支持的路径仅安装应用；不要使用构建输出中的组合烧录命令替换平台分区。`CONFIG_PET_SOCIAL_CHANNEL` 选择双方共用的 ESP-NOW 信道，默认为 1。LVGL 内存池为 64 KiB，当前场景和帧解码缓冲区由应用持有。

<a id="host-checks"></a>
## 主机检查

准备 C 编译器、CMake、Ninja、OpenSSL 3、Python 和 Pillow 后运行：

```sh
python3 plays/sugarat-pet/tools/pack_characters.py --check
python3 plays/sugarat-pet/tools/check_host.py --output /tmp/sugarat-pet-host
```

检查使用 AddressSanitizer 和 UndefinedBehaviorSanitizer 执行真实的养成逻辑、旧记录读取器、家族记录、文件存储、社交状态机、密码实现、BSP 带位移守卫的点按、应用手势和 LVGL 视图。覆盖屏幕下部 18 个上滑起点、跟手移动、背景冻结、独立按钮间隙、成员浏览的两端限制、返回与确认的区别以及动画释放。无线数据报与设备服务使用原生适配器。两个端点覆盖丢包、乱序、重复、篡改、持久写入前后失败和重启恢复。输出包括文本快照、圆屏图片、`animated-family.gif` 和 `controls-swipe.gif`。这些检查不会打开串口或 Wi-Fi 硬件。

<a id="saving-and-time"></a>
## 保存与计时

首次运行家族版固件时，从私有 NVS 导入最新且有效的 56 字节 Ember 记录，原记录不被替换。新家族使用平台应用数据接口提供的 `sugarat_pet` 目录，交替保存两个 8 KiB 文件 `family-a.dat` 和 `family-b.dat`。该文件系统不可用时，私有 NVS 键 `family_a` 和 `family_b` 保存去掉零填充的同一份有效记录，每份最多 3 KiB。已有紧凑记录始终作为家族数据来源，即使之后应用数据文件系统恢复可用。NVS 写入要求能容纳下一份最大记录，且在库自身预留空间之外，为其他使用者保留 128 个可用条目。文件写入须刷新并同步，NVS 写入须提交，两者均须读回确认后才报告成功。版本未知、记录全部损坏或写入未确认时，会停用后续写入与繁育；单份损坏可从另一份有效文件恢复。存储不可用或共享 NVS 容量不足时，可临时养成并显示提示。未格式化的应用数据分区不会被自动格式化。不会清空共享 NVS 或分区。旧固件无法读取家族进度，详见[迁移指南](../../../docs/upgrade-guide/v0.2.1-rc.2/pet-family-save/guide.zh.md)。

养成操作后和每 30 秒有效前台时间会自动保存。系统暂停、返回启动器和正常关机时会请求保存；保存未确认会阻止软件返回启动器。物理断电仍可能丢失自上次确认写入后的变化。Flash 操作使用 BSP 的触摸互斥窗口。只有选中的伙伴推进养成，陪伴孵蛋时双亲暂停；系统控制打开、离开应用或关机期间冻结进度。每级成长需 30 分钟有效陪伴，Lv31 成年。孵育需 30 分钟有效陪伴，亲本繁育休息需 120 分钟有效陪伴。疏于照顾时健康下限为可恢复的 20。

<a id="nearby-pairing"></a>
## 碰面配对

碰面在 Wi-Fi 可用时启动应用独占、使用内存配置的 ESP-NOW 工作站。双方必须明确选择彼此。首次碰面使用临时 P-256 密钥协商，并由两位用户核对六位码后确认；再次碰面使用保存的好友密钥认证。应用数据包使用分方向的 AES-GCM 密钥、新序号对应的 nonce 和重放拒绝。无线回调仅将有上限的数据报入队，LVGL 所有者处理业务。关闭碰面、打开系统控制或关机时释放无线资源。

打招呼、送心意、一起玩分别在对端接受后贡献一个亲密标记。繁育要求双方同意、成年、能量至少 30、有空蛋位和家族位置、完成三种互动且没有待完成事务。排除已知的自身、双亲与兄弟姐妹。每位双亲各贡献两份基础血统中的一份。两个设备计算并核对相同的后代摘要，各自获得独立身份且至少一个可见特征不同的孩子。准备计划、提交决定和回执均持久化并保持幂等。准备后断连的事务保持待同步，应让相同的活跃双亲再次碰面完成。双亲继续留在家族中。上限为六位本地成员、一颗蛋、十六位好友和十六份保留的事务回执；容量满时拒绝额外繁育，不删除伙伴。

<a id="sources-and-limits"></a>
## 来源与限制

[upstream.json](upstream.json) 固定未经修改的 MIT 许可 epet 源码。[角色元数据](assets/characters/manifest.json) 固定六份通过 ImageGen 为本项目生成的源图集；`tools/pack_characters.py` 编译为 96 帧经过锚点整理的 96×96 索引色 RLE 资源。每族具有各四帧的待机、眨眼、进食和开心动作。睡眠使用闭眼姿态和呼吸起伏，出生使用蛋的晃动和开心揭晓。成长目前缩放同一套美术。十项特征被保存和遗传，其中体宽、配色、额头花纹和动作节奏参与显示。独立成长形态、眼睛／耳朵／嘴的分层部件、专用难过／出生动作、音效、成员归档和独立好友相册不在本次构建中。

Pixel-Pets 和 pet-esp 提供社交与遗传设计参考，未导入其代码或角色素材。BSP、LVGL 和 Watch 保留各自许可。实体 ESP-NOW 互通、无线距离、实际触摸、续航、启动器共存和断电行为需要针对本版固件进行双设备验收。原生渲染与 ESP32-S3 构建成功不代表这些验证结果。
