# Sugarat Squad Talk

[English](README.md) | 中文

## 概要

Squad Talk 通过 ESP-NOW 直接连接两台谷仓 ESP32-S3 圆屏徽章。选择相同频道，等待 `BUDDY ONLINE`，按住 `HOLD TO TALK` 说话，松开后收听。英文奶油白与紫色界面使用大指纹按住区域、粗圆字体和随状态变化的填色。应用不需要路由器、手机、账号或服务器。[validation.json](validation.json) 分别记录固件构建、主机测试和设备验收。

<a id="use"></a>
## 使用

两台徽章安装相同版本的应用。在屏幕背景左滑切换到下一个逻辑频道，右滑切换到上一个；频道 01–08 首尾循环，每次启动从 01 开始。从指纹按钮以外、顶部控制中心手势条以下的位置起手。每次滑动在松开时只切换一个频道，点击、短距离拖动和以纵向为主的移动不切换频道。应用自动选择首个匹配设备，在对方离开或频道改变前保持此选择。本版本每组支持一对设备。`FIND BUDDY` 表示尚未收到匹配设备的回应，不代表已经建立无线连接。

按住指纹按钮申请发言。`CALLING...` 等待对方确认，`RELEASE TO LISTEN` 表示正在发送。接收方显示 `LISTENING...` 并播放收到的声音。冲突、超时或暂停通话后，双方都需要重新按下才能发言。同时申请时设备地址较小的一方优先。每次发言最多 30 秒；结束包丢失时，接收方在 600 毫秒没有声音数据后释放状态。连续 3 秒没有有效对方数据包时，设备发现结果过期。

从指纹按钮起手的拖动不切换频道，移出椭圆会取消发话，重新按下后才能继续。手指移出按钮、打开控制中心、屏幕休眠或退出应用都会结束发送。关闭控制中心或唤醒不会恢复之前的按住状态。顶部下滑保留平台的音量、亮度及 Exit/Power 控制。严重音频或无线错误会停用语音并显示 `RESTART APP`，点击按钮重启固件。指纹是触摸提示图案，不扫描或识别指纹。

<a id="build"></a>
## 构建

激活已有的 ESP-IDF 5.5.4 和 ESP32-S3 工具链环境，在 资源包根目录运行：

```sh
idf.py -C plays/squad-talk -B /tmp/squad-talk-build build
```

只交付 `/tmp/squad-talk-build/squad_talk.bin`。项目名 `squad_talk` 是稳定的启动器身份，应用版本为 0.1.3。保留平台分区表、引导程序配置、电源锁存和启动器 Exit 入口。烧录前必须通过设备检查确认实际可写应用地址。应用不改变分区、otadata 或其他应用的数据。

<a id="host-checks"></a>
## 主机检查

准备 CMake、Ninja、C 编译器和 Pillow 后，运行：

```sh
python3 plays/squad-talk/tests/check_host.py --output /tmp/squad-talk
```

命令在 AddressSanitizer 和 UndefinedBehaviorSanitizer 下运行真实协议、独立 ADPCM 数据块、LVGL 界面和触摸控制器。两个模拟设备覆盖 200 次交替发言、同时请求、频道过滤、重复数据包、提前松开、设备过期和非法包。真实 LVGL 指针事件检查按住、松开、移出按钮、左右滑动、频道首尾循环、短拖与斜向及顶部手势过滤、发话与切频道互不干扰，以及浮层和休眠取消。[本地英文输出快照](tests/expected/ui-text.txt) 覆盖八个状态。导出的 `preview-en.png` 来自实际界面渲染，不是设备截图，也不能证明无线距离、音质或端到端延迟。

<a id="communication-and-failures"></a>
## 通信与故障

所有逻辑小组共用无线信道 6。固件以站点模式初始化 Wi-Fi 无线硬件，不加入热点，不启动热点或 IP 服务。设备发现使用广播，语音与发言控制通过选中设备的地址发送。逻辑分组只过滤应用数据包，不加密语音。此构建用于附近两台设备演示，不用于保密通信，也不承诺覆盖距离。

语音使用可独立解码的 16 毫秒、16 kHz 单声道 IMA ADPCM 数据块，并带有 24 字节的版本化包头。播放前验证长度、版本、小组、编码状态、对方启动身份和通话身份。重复或迟到的序号被丢弃，丢失一块数据不会破坏后续解码状态。无线工作任务串行发送，麦克风和 Wi-Fi 回调只复制有界数据到队列。音频队列满时丢弃声音，而松开和暂停输入使用独立同步状态。发送完成回调缺失时停止无线工作，避免将迟到回调误认为新数据包的完成结果。

应用内音频组件在播放前缓冲 64 毫秒，短语音最多等待 80 毫秒，播空后重新缓冲 48 毫秒。唯一播放写入者在清理旧通话时等待音频任务确认。启动时预热麦克风一次，只在对方批准且按钮按住时发送采集声音。语音峰值限制在徽章文档给出的扬声器范围内。音频播放（优先级 8）、麦克风采集（9）和无线传递（7）运行于 CPU 1，高于 CPU 0 的界面任务（6）。音量变化只重绘活动条，指纹区域保持静态。通话时的 `FLOW` 日志报告已发送块数、累计接收、丢包与队列丢弃数、排队样本数和工作循环的最大间隔。这些设置需要双机音质和距离验收。应用不请求或存储 Wi-Fi 密码，频道选择仅保存在内存中，也不保存声音。

<a id="hardware-and-sources"></a>
## 硬件与来源

工程由校验通过的本地谷仓开发包 0.2.1 初始化：ESP-IDF 5.5.4、LVGL 8.3.11、360×360 ST77916、CST816 触摸、32 MiB Flash 和 8 MiB Octal PSRAM。麦克风与扬声器保留 BSP 的 I2S 接线。应用基于随包 Game 控件，采用奶油白、紫色与荧光绿配色、220×350 像素、下半部伸出屏幕的椭圆指纹区域和 Nunito Black 英文字形。文字位于实际圆形屏幕内，指针测试区分椭圆点击区域和矩形角落。[Nunito 的 OFL 许可](assets/fonts/OFL.txt)覆盖随包字体源文件和生成的子集，运行 `python3 plays/squad-talk/tools/make_ui_fonts.py` 可重新生成。[upstream.json](upstream.json) 固定已检查的 atomic14 对讲项目来源，[MIT 声明](licenses/atomic14-MIT.txt) 和基础工程声明随项目分发。双机通话协议、独立编码数据块及硬件适配由本应用维护。

按开发包的[部署说明](../../../hardware-kits/sugarat-sdgoods/references/deployment.md)操作。只有用户明确要求时才跳过完整私有备份。启动器安装、单应用烧录、写入字节校验、启动、触摸、麦克风、扬声器、半双工对话、距离和电源行为分别验收。固件编译成功或模拟对话通过不代表真实设备行为已验证。
