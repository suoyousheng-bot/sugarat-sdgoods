# SDGOODS Wi-Fi setup UI

English | [中文](README.zh.md)

Install `sdgoods-wifi-ui` with `target=esp-idf` under the SDGOODS firmware project root. Its dependency installs the network component. Add `sugarat_wifi_ui` to `main/REQUIRES`; initialize the BSP/LVGL and network owner before calling `sugarat_wifi_ui_create(wifi)` and `lv_scr_load(screen)` on the LVGL thread. Check both returned error/pointer values. Delete the screen before destroying Wi-Fi. Screen deletion removes the UI timer and frees its state.

## Success callback and application screens

Use `sugarat_wifi_ui_default_config()`, set `on_connected` and `user_data`, then call `sugarat_wifi_ui_create_with_config(wifi, &config)`. The callback receives `(setup_screen, const sugarat_wifi_event_t *, user_data)` on the LVGL thread after DHCP, credential commit and hotspot/service shutdown. It can create/load the application screen and delete `setup_screen` synchronously. The component does not access deleted UI state after returning from the callback. Copy event data before retaining it. The user-data owner must outlive the screen.

A current successful connection is replayed once on the first timer tick, so startup reconnects cannot miss navigation while the screen is being created. Creation itself never calls the handler. Each later connection sequence triggers automatic navigation once; repeated polling does not repeat it. Set `notify_current_connection=false` when reopening settings to keep the settings screen open. With `on_connected` configured and a live saved connection, the setup home shows an application-return arrow at the upper left. Pressing it invokes the same navigation callback with the retained connection event, even if that sequence was already delivered; do not discard this explicit request by deduplicating the event sequence in application code. If the setup hotspot is open, the component requests closure and waits for confirmation before returning. Save failures, lost connections and hotspot-close failures withhold return; a busy or failed close remains visible for retry. Back arrows inside network, password and hotspot pages return to the setup home. Deleting the screen cancels future delivery. The original `sugarat_wifi_ui_create` remains available with no navigation callback.

For a runnable placeholder application, compile `examples/setup_flow.c` in the consuming application's source list, add `examples/` to its include paths, include `setup_flow.h`, and load `sugarat_wifi_example_create(wifi)`. The example replaces setup with a vector status graphic and an App ready home, and its Wi-Fi settings button reenters setup with current-success replay disabled. It supplies no credentials, BSP initialization, partition changes or application entry point. Replace its `connected` callback with the project's own screen; the networking and input code remain reusable. Check the returned screen before loading it.

The default English screen uses a light grouped layout with blue primary actions and offers two methods: select a scanned network on-device and enter its password with a grouped touchscreen keyboard; or connect a phone to the displayed open hotspot without entering a hotspot password and open its local webpage. The language button switches to Chinese. Both methods use the same network state and scan generations. No editable SSID field is created. Busy, scan, join, success, failure and save-failure outcomes are visible. Successful credentials reconnect after restarting; the Connected button opens connection details and an explicit Forget Wi-Fi action.

All setup controls stay within the documented 240x240 safe rectangle at (60,60) on the 360x360 round display. The home screen uses two 68px-high method cards with Wi-Fi scan and phone-hotspot icons. Network pages show two 54px-high choices, with previous/next and scan controls. Every touch target is at least 48x48px. The password keyboard shows six large keys per page: select lowercase, uppercase, digits or symbols, then use the right-arrow icon for more characters and the keyboard icon to change groups. Vector eye, backspace and space icons control password visibility, deletion and spaces; Connect remains a labeled action. Icon graphics do not intercept taps on their buttons. Button labels and paired card text are vertically centered. Hotspot instructions and connection details are centered horizontally on the round screen. Change the interface language before opening the password page. Passwords are concealed by default and may be revealed. The 16px and 20px licensed Noto Sans SC Medium subsets are distributed with their SIL OFL notice; they cover all component UI strings, ASCII and a Chinese subset, not every possible Unicode SSID. Extend glyph coverage for uncommon network names. LVGL 8.3.11 is required.

No BSP pins, partition table, application entry point, native-preview adapter or device observations are installed. A desktop preview needs its own radio implementation and must not link ESP-IDF radio code directly. Verify real touch, keyboard, language text, scrolling and both network paths on the device. Compilation alone does not verify them.
