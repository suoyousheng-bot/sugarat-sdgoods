# SDGOODS audio

English | [中文](README.zh.md)

Install `sdgoods-audio` with `target=esp-idf` under the SDGOODS firmware project root and add `sugarat_audio` to `main/REQUIRES`. Replace the template's `sdgoods_audio_init()` call with `sugarat_audio_init(&config)` after LVGL and touch initialization, and check the returned error. The component owns I2S0 TX for the speaker, I2S1 RX for the microphone and the PA enable on GPIO 3. The ESP32-S3 has no other I2S ports, so a firmware that also calls `sdgoods_audio_init()` receives the I2S driver error. BSP `sdgoods_audio_get_volume()`, `sdgoods_audio_set_volume()` and `sdgoods_audio_bgm_stop()` remain safe, so the control-center volume page keeps working; `sdgoods_audio_bgm_start()` and BSP recording or playback fail while this component owns the ports.

```c
sugarat_audio_config_t audio = sugarat_audio_default_config();
audio.on_event = on_audio_event; /* runs on the audio task */
ESP_ERROR_CHECK(sugarat_audio_init(&audio)); /* instead of sdgoods_audio_init() */
ESP_ERROR_CHECK(sugarat_audio_tone(1000, 300));
```

## Operations

One audio task runs one operation at a time: tone, sweep, PCM playback, WAV playback, recording, recording playback or the microphone level meter. A new request or `sugarat_audio_stop()` ends the current operation between blocks and publishes STOPPED. Audio is 16 kHz 16-bit PCM; playback mixes stereo to mono. `sugarat_audio_play_wav()` accepts RIFF PCM 16-bit 16 kHz with one or two channels and returns `ESP_ERR_NOT_SUPPORTED` for other encodings or rates. Callers keep PCM and WAV buffers valid until completion, a newer request or a stop. Recordings are stored in PSRAM up to `record_max_ms` (default 5000, 32 KB per second); `process_recording` removes DC and rumble, normalizes loudness and fades the ends. `sugarat_audio_write_wav_header()` writes a 44-byte header for exporting a recording.

Playback follows the control-center volume when `follow_system_volume` is true and `volume_percent` otherwise. Each operation enables the PA after 80 ms of silence and disables it after a 60 ms tail to avoid pops; volume changes ramp across one 16 ms block, and volume 0 plays silence with the PA on. The foundation BSP's `sdgoods_audio_set_volume()` switches the PA off whenever BSP music is idle. The component switches it back on at the next block, so audio continues, but dragging the volume slider during playback pops. For pop-free volume changes, limit that call in `components/sdgoods_board/src/sdgoods_audio.c` to BSP music: replace `pa_apply();` in `sdgoods_audio_set_volume()` with `if (s_bgm_run) { pa_apply(); }`. The `ip-agent` application includes this change. `sugarat_audio_get_status()` reports the state, microphone level, peak and dBFS, progress, recording length, effective volume and last error. `config.on_event` runs on the audio task: copy the event or post it with `sdgoods_lvgl_post()`, and never call LVGL there.

## Streaming

`sugarat_audio_stream_start(&config)` serves voice conversations: the microphone runs continuously and `config.on_mic` receives 16 kHz mono blocks every 16 ms on the microphone task, while the speaker plays whatever `sugarat_audio_stream_write()` queues. Call it from a worker task, never from the audio task; it stops the current operation first. The PSRAM playback queue holds `playback_buffer_ms` (200–10000) and is allocated by the first start; later starts keep that size. One task writes; the write never blocks and returns the whole samples accepted. A queue created by `xStreamBufferCreateWithCaps()` holds one byte less than requested, so the write never splits a sample: otherwise a full queue shifts every later sample by one byte, which plays as full-scale noise. Flushing drains the queue on the audio task instead of resetting it while the writer runs. Playback waits until 200 ms are queued, or 250 ms after a shorter burst arrived; a queue that runs dry fades out over 4 ms and resumes after 120 ms are queued again, so late network packets do not become audible holes. `sugarat_audio_stream_flush()` discards queued playback, for example when the user interrupts a reply. Status adds `out_level_percent` (speaker RMS, −50 to 0 dBFS) and `out_active` (audio reached the speaker within 120 ms) for mouth or level animation. The PA switches on when audio is queued and off after 800 ms without audio; each reply logs its played length and the number of times playback ran dry. `sugarat_audio_stop()` ends streaming.

## Verification limits

Hardware acceptance on an SDGOODS round badge with ESP-IDF 5.5.4 covered tones, sweeps, volume changes during playback, the microphone level meter, 3 s recording, recording playback and WAV playback. Streaming was verified in the IP Agent application during voice conversations: replies up to 17 s, which fill the 10 s queue, played without dry-queue gaps or noise. The board's amplifier and speaker are driven at about a quarter of full scale; the BSP's own sounds peak near 8000, so limit streamed speech peaks to about 9000 or it crackles. With the BSP volume change above, playback can continue while the control center adjusts the volume; otherwise stop audio when the control center opens or the application pauses. Audio quality depends on the enclosure and speaker; verify it on the device. The component does not decode compressed formats, resample or change BSP pins, partitions or the application entry point.
